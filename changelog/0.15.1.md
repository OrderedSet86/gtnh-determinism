# gtnh-determinism 0.15.1

Since `90eee857d0cd62c1e596bf0f2a9507a92ce97a16` (0.15.0).

## Summary

- **0.15.0 crashes at startup. 0.15.1 fixes the crash.** The release workflow attached the wrong build
  output to the 0.15.0 release. 0.15.1 has the same mod source as 0.15.0 and the same worldgen.
- **The release jar is now selected by name, and the release workflow fails on a jar without JvmDowngrader stubs.**

## Fixed

### The 0.15.0 jars were an intermediate build output

0.15.0 is the first release built with JvmDowngrader. With JvmDowngrader, the build writes two more jars
beside the release jar: `-downgraded.jar` and `-predowngrade.jar`. Those two jars have the development (MCP)
names and no JvmDowngrader stubs. `release.yml` took the first jar in the list that did not end in `-dev`
or `-sources`. That jar was `-downgraded.jar`.

Effect on GTNH 2.9.0, Java 17, `RWG2_CONTINENTS`: the server stopped 17 s after launch with

```
InvalidMixinException: @Shadow field boundingBox was not located in the target class
net.minecraft.world.gen.structure.StructureComponent. Using refmap mixins.gtnhdeterminism.refmap.json
```

In the published jar, `StructureComponentChestMixin` refers to `boundingBox`. In the release jar,
`StructureComponentChestMixin` refers to `field_74887_e`. `worldgenprobe-0.15.jar` had the same defect.

`release.yml` now filters out `-dev`, `-sources`, `-downgraded` and `-predowngrade`, and fails unless exactly
one jar is left. A new step fails if `gtnhdeterminism-*.jar` or `worldgenprobe-*.jar` has no stubs under the
jar's package prefix, or if a class in the jar calls a stub outside that prefix. `scripts/build-jar.sh` uses the same filter.

## Tested

A local build of 0.15.1 with the jar selection of `release.yml`. `scripts/run-probe.sh`, seed 42, radius 2
(7 × 7 chunks), chunk order `rows`:

| pack | world type | Java | result |
|---|---|---|---|
| 2.9.0 | `RWG2_CONTINENTS` | 17 | boots, world generated, 0 mixin errors, all six `Rwg2*` mixins selected |
| 2.9.0 | `RWG2_CONTINENTS` | 25 | same |
| 2.8.4 | `rwg` | 17 | boots, world generated, 0 mixin errors, all five RWG mixins selected |
| 2.9.0 | `RWG2_CONTINENTS` | 17 | the published `gtnhdeterminism-0.15.jar`: stops at startup, error above |

The new stub check passes on the jars of the local build, and fails on both published 0.15.0 jars.
