# Tinkers' Construct materials findable in chest loot

Which Tinkers' Construct tool materials a player can obtain from world-generated chests, and what
each one is worth. Generated by [`scripts/tc-chest-materials.py`](../../scripts/tc-chest-materials.py).

```bash
./scripts/tc-chest-materials.py \
  --loot results/2026-08-29-post-only-loot/chestloot-f9.csv \
  --config ~/.cache/gtnh-determinism/daily-707/config \
  --out results/2026-08-29-tc-chest-materials
```

Pack: GTNH daily-707, `~/.cache/gtnh-determinism/daily-707`. Loot source:
`results/2026-08-29-post-only-loot/chestloot-f9.csv` (md5 `7f875d93a5c4cf24315cabd9ff93d782`).
Statistics: that pack's `config/IguanaTinkerTweaks/MaterialDefaults.cfg`, a runtime dump of the live
`TConstructRegistry.toolMaterials`.

## Scope

Rows where `source = roguelike`, or `source = chestgenhooks` and `phase = post`. Since fix F9 the
`post` table is the whole world's table
([`../2026-08-29-post-only-loot/README.md`](../2026-08-29-post-only-loot/README.md)), so these two
sources are the loot a player can reach in a current world.

That selection holds **244 tool-part rows** covering **21 materials**, in three buckets only:

| bucket | rows |
| --- | ---: |
| `roguelike` / `WEAPONS`, levels 0-4 | 99 |
| `roguelike` / `TOOLS`, levels 0-4 | 81 |
| `chestgenhooks` / `TinkerHouse` | 64 |

**No other post-phase chest category drops tool parts at all.** `villageBlacksmith` and `bonusChest`
drop assembled tools instead; those are in `premade-tools.csv`. Every other TConstruct-family loot
row is listed in `excluded.csv` with the reason it is not a material.

## Answers

**Only two pickaxe heads exist in chest loot: Stone and Flint, both from `TinkerHouse`.** Nothing in
Roguelike Dungeons drops a pickaxe head. Chest loot cannot raise mining tier; it can only supply a
starter pickaxe. Every other head type is well covered, so this is specific to pickaxes.

**Roguelike level is the material tier.** Each material appears at one dungeon level and one level
only, except Obsidian, which spans levels 2 and 3. Level 0 gives Wood, Flint and Cactus; level 1 Iron,
Bronze and Pig Iron; level 2 Obsidian, Queen's Gold and Electrum; level 3 Steel, Alumite and Magnetic
Steel; level 4 Cobalt, Ardite and Aeon Steel. Reaching the bottom floor is the whole reward.

Copper, Stone, Bone, Slime, Blue Slime and Paper never appear in a Roguelike dungeon. They come from
`TinkerHouse` only, which is also the only source of a pickaxe head.

**Best head found: Cobalt** — harvest level 8, durability 600, mining speed 11, attack 4, Reinforced
II. Roguelike level 4 only. Ardite matches its durability class with harvest level 7 and Stonebound
2, so it mines faster as it wears but starts slower.

**Best rod found: Ardite tough rod, handle modifier 2.10 (+110% durability).** For tier-1 tools the
best is the Electrum tool rod at 1.50 (+50%). Electrum's own durability of 48 is irrelevant in a rod
slot, where only the handle modifier is read — it is a poor head and an excellent rod.

**Cheapest Reinforced: Obsidian, Reinforced III.** Reinforced takes the maximum across every part, so
an Obsidian binding, crossbar or guard grants Reinforced III to a tool with any head. Obsidian drops
as 17 different parts, more than any other material, and is available from `TinkerHouse` at 1.17
expected parts per chest as well as from Roguelike levels 2 and 3. Nothing else in chest loot exceeds
Reinforced II.

**Tough-tier parts are findable, not just craftable.** Hammer heads, excavator heads, scythe heads,
large sword blades, large plates, tough rods and tough bindings all drop, in Steel, Magnetic Steel,
Alumite, Aeon Steel, Ardite and Cobalt (plus Electrum, Queen's Gold and Obsidian for the non-head
tough parts). These need a Tool Forge and large material quantities to craft, so a Roguelike level
3 or 4 find skips a substantial amount of progression.

**Some found parts cannot be crafted at all.** Loot generation ignores `restrictions.cfg`, which
rewrites which parts a restricted material may be made into. Four materials drop parts that are
uncraftable in this pack:

| material | chest-only parts |
| --- | --- |
| Obsidian | sword blade, large sword blade, bow limb, crossbow limb |
| Wood | sword blade, axe head, shovel head, knife blade, arrowhead, frying pan head, wide guard, hand guard |
| Cactus | sword blade, axe head, shovel head, arrowhead, frying pan head, wide guard, hand guard |
| Flint | tool rod, binding, frying pan head, wide guard, hand guard |

The Obsidian sword blades are the significant ones: attack 2 is poor, but Reinforced III on a blade
that cannot otherwise be made is a real find.

## Crossbows

Crossbows are scored from a different registry, so they get their own table: `crossbow-limbs.csv`.

A crossbow is limb + body + bowstring + tough binding
(`forks/TinkersConstruct/src/main/java/tconstruct/weaponry/weapons/Crossbow.java:366-383`). Only two
of those four affect its projectile stats
(`weaponry/WeaponryHandler.java:208-243`):

```
DrawSpeed   = trunc(trunc(limb.drawspeed * string.drawspeedMod * 2.5) * 0.75)   ticks
FlightSpeed = limb.flightSpeedMax * string.flightSpeedMod * 1.5
Durability  = limb.durability * body.handleModifier
```

**The body and the tough binding contribute nothing but durability and traits.** Only the limb
material and the bowstring set draw and flight speed.

**`drawspeed` is a duration in ticks, so lower is better.** It is loaded straight into the reload
countdown (`Crossbow.java:119-126`) and decremented once per tick. **`flightSpeed` is projectile
velocity and multiplies bolt damage directly** — `damage = speed * baseAttack` in
`library/entity/ProjectileBase.java:186-215`. The base attack comes from the bolt's head material,
not from the crossbow, so flight speed scales whatever ammunition you feed it.

Values below use plain String bowstring, whose three modifiers are all 1.0. Flamestring (Natura)
multiplies draw by 1.1 and flight by 1.2; Enchanted Fabric (Thaumcraft) multiplies draw by 0.8 and
flight by 0.9 and grants +1 modifier.

| limb material | draw | flight | flight/s | limb durability | reinf. | verdict |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| **Cobalt** | 4.20 s | 7.95 | **1.893** | 600 | 2 | best sustained output, and the best limb durability |
| **Alumite** | 4.20 s | 7.50 | 1.786 | 413 | 2 | same reload as Cobalt for 6% less damage; strictly beats Ardite |
| **Steel** | 5.60 s | **8.25** | 1.473 | 300 | 2 | highest damage per bolt, slowest of the strong tier |
| **Ardite** | 5.10 s | 7.35 | 1.441 | 455 | 0 | dominated by Alumite on both axes |
| Electrum | 1.85 s | 2.25 | 1.216 | 48 | 0 | fastest reload available, roughly a quarter of Steel's per-bolt damage |
| Magnetic Steel | 1.85 s | 2.25 | 1.216 | 384 | 1 | identical projectile stats to Electrum with 8x the durability |
| Obsidian | 10.20 s | 1.50 | 0.147 | 67 | 3 | worst on both axes, and the limb cannot be crafted |
| Aeon Steel | — | — | — | 617 | 2 | **unusable, see below** |
| Queen's Gold | — | — | — | 75 | 0 | **unusable, see below** |

**Cobalt is the answer for a crossbow**, from Roguelike level 4. It has the best sustained output,
the best limb durability of any findable material, and Reinforced II. Steel, from level 3, is the
pick if you care about a single hard-hitting shot rather than throughput.

**Aeon Steel and Queen's Gold crossbow limbs are dead items.** Tinkers' Defense registers tool
materials for metadata 201 and 202 but never calls `addBowMaterial`
(`Tinkers-Defense/.../TinkersDefense.java:243-246, 288-290`; a tree-wide grep for `addBowMaterial`
finds nothing). With no `BowMaterial`, `Crossbow.buildTool` returns early
(`Crossbow.java:391-393`) and `WeaponryHandler` denies the craft
(`WeaponryHandler.java:213-217`). They still appear in chest loot because `DynamicToolPart.getSubItems`
iterates the default part materials with no bow filter. This affects bow limbs too. Aeon Steel is
otherwise the best head material in the table, which makes the limb form especially misleading.

**Obsidian limbs are loot-only.** `restrictions.cfg` lists Obsidian and grants it `crossbowbody` but
not `crossbowlimb`, so the limb cannot be crafted or cast — but it is also the worst limb in the
game, so this costs nothing.

**The body is not findable.** No `partCrossbowBody` appears anywhere in the loot table, so a crossbow
cannot be assembled from chest finds alone. Since the body only multiplies durability through its
`handleModifier`, craft it from the highest handle modifier available.

The two GregTech-derived limbs deserve a note on provenance. `BowMaterial` is dumped by no config
file, so their draw and flight speeds are recomputed from the GregTech tool quality that the pack's
own `MaterialDefaults.cfg` implies, which both `attack` and `handleModifier` independently put at 2
for Electrum and for Magnetic Steel. The `GT5-Unofficial` checkout on this machine says Magnetic
Steel is quality 3, which would give 2.80 s and 3.75 instead. The checkout is a different GregTech
version from the pack's `gregtech-5.09.54.115.jar`, so the dump is preferred. Every other row is a
literal from `TinkerWeaponry.java` and needs no derivation.

## Reading the numbers

**Roles.** A material's worth depends on the slot its part fills, so there is no single score. The
slot behaviour is from `ToolBuilder.buildTool`
(`forks/TinkersConstruct/src/main/java/tconstruct/library/crafting/ToolBuilder.java:173-265`):

| role | effect |
| --- | --- |
| head | sets base durability, mining speed, harvest level and attack |
| head-add | an accessory or extra of `durabilityType` 2; adds its durability and attack to the head total, then the sum is averaged over the heads. Large plates on the hammer, excavator, cleaver and lumber axe; the shovel head on the mattock |
| handle | `durabilityType` 1; contributes `handleModifier`, which multiplies durability |
| trait-only | `durabilityType` 0; contributes nothing but Reinforced and Shoddy |
| bow-limb | bow and crossbow limbs; identified by tool material but scored from a separate `BowMaterial` registry, so the tool statistics in this table do not describe them. See the crossbow section, and note that an `as_bow_limb` of `yes` does **not** mean the limb is usable — Aeon Steel and Queen's Gold have no `BowMaterial` at all |

Reinforced and Shoddy propagate from **every** part whatever its slot: Reinforced is the maximum over
the parts, Shoddy their mean. That is why a trait-only part can still be worth taking.

The whole tool:

```
BaseDurability = trunc(head.durability * rod.handleModifier * tool.durabilityModifier)
MiningSpeed    = head.miningSpeed
Attack         = head.attack + tool.baseDamage
HarvestLevel   = head.harvestLevel
```

Tool durability modifiers: hammer 4.5, scythe 3.0, excavator 2.75, battleaxe / cleaver / lumber axe
2.5, broadsword 1.2, rapier 0.7, everything else 1.0.

**Harvest levels run 0 to 9, not vanilla's 0 to 3**
(`IguanaTweaksTConstruct/.../util/HarvestLevels.java:25-35`). Tier names in `materials.csv` come from
the comment IguanaTweaks generates into `MaterialOverride.cfg`, which is written from the live
`HarvestLevels.getHarvestLevelName`: 0 Stone, 1 Copper, 2 Iron, 3 Tin, 4 Redstone, 5 Obsidian,
6 Ardite, 7 Cobalt, 8 Manyullyn. `HarvestLevelNamesDefaults.cfg` in the same directory disagrees from
tier 3 upward, giving Bronze and Steel for tiers 3 and 4. The generated comment is preferred because
it reflects the running game, but the conflict is unresolved and the numeric level is the safe thing
to compare.

**A found pickaxe head mines one tier below its material.** IguanaTweaks subtracts 1 from
`HarvestLevel` for picks and hammers at craft time, and the tool earns it back once through a
separate mining-experience bar (`IguanaTweaksTConstruct/.../leveling/LevelingLogic.java:112-122`,
gated on `main.cfg` `pickaxeBoostRequired=true`, which is on in this pack). The subtraction is
skipped when the head is already tier 0, so a Stone pickaxe stays at 0 and a Flint pickaxe starts at
0 rather than 1.

**`shoddy` carries two traits in one number.** Positive is Stonebound, where speed rises as the tool
wears; negative is Jagged, where damage rises as the tool wears. The `trait` column names it.

**`xp_amount` multiplies the experience required to level a tool**, so a higher value is worse. It is
1.0 for every material in this table.

**`exp_*` columns are expected counts, not probabilities**: `mean(rolls_min, rolls_max)` times
`pick_chance_per_roll`, summed over that material's rows in the bucket. Chest rolls draw with
replacement from the weighted pool, so a value above 1 is possible and means more than one part is
expected per chest. Roguelike levels are separate columns because one chest sits at one level.

**`durability_x_best_rod`** is the material's durability times 1.50, the best tool-rod handle
modifier in chest loot (Electrum). **`durability_x_best_tough_rod`** uses 2.10, the best tough-rod
modifier (Ardite), and is filled only for materials that drop as a tough-tier head. Both ignore the
per-tool durability modifier.

## Verification

The script exits non-zero rather than emitting a plausible-looking table if any of these fail.

1. **Mapping completeness.** All 21 metadata values resolve to a material name through
   `TinkerTools.MaterialID` (0-18), `tinkersdefense.cfg` (201, 202) and `TGregworks.cfg`'s
   `material-id` section (1595, 1647), and each resolved name has a block in `MaterialDefaults.cfg`.
2. **Name cross-check.** The server writes the material's localized name into the loot CSV's
   `display_name`. Every part row's display name must start with the mapped material's expected name,
   held in a checked-in alias table, and the remaining part suffix must be identical across all
   metadata values of that item. A pack that renames a material fails here instead of silently
   attaching the wrong statistics.
3. **Override guard.** `MaterialOverride.cfg`'s `materials` block must be empty. If it were not, it
   would supersede `MaterialDefaults.cfg` and this report would be wrong. It is empty in daily-707.
4. **Restriction vocabulary.** Every part name the script maps to must appear in the `partnames are:`
   list that `restrictions.cfg` prints.
5. **End-to-end arithmetic.** For all 6 assembled tools in loot, the script recomputes
   `BaseDurability`, `MiningSpeed`, `Attack`, `HarvestLevel` and `Unbreaking` from the material table
   and the `ToolBuilder` formulas, and requires exact equality with the NBT the server wrote. **All 6
   match**, including the Bronze pickaxe at `285 x 1.25 x 1.0 = 356` with harvest level `4 - 1 = 3`
   and the Bronze broadsword at `285 x 1.25 x 1.2 = 427` with harvest level 4. This checks the
   statistics table and the formulas together against ground truth rather than against each other.
6. **Portability.** See the cross-version section below.

Two things this report does not check. The crossbow table is derived from source literals and from
the GregTech tool quality implied by the config dump, not from a runtime dump of
`TConstructRegistry.bowMaterials`, because no config file writes one; the crossbow section states
where each row's numbers come from and flags the one value that a different GregTech version would
change. And `display_name` is generated server-side; a client with a GregTech language override may
show a different name for the same metadata value, which is why the numeric `meta` is the join key.

## Cross-version

Re-running against `~/.cache/gtnh-determinism/template-2.8.4/config` with the same loot CSV is the
portability check. Differences between the two packs' material statistics are recorded in
`version-diff.md`. A routing decision taken on one pack version does not carry to the other without
reading that file.
