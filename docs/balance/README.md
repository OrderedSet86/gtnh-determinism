# Balance-equivalence evidence

Statistical evidence that the determinism jar does not meaningfully change worldgen frequencies —
the supporting material for upstream adoption and for the speedrun community's own review.

## Method

Two arms, identical seed lists, cold runs (fresh JVM per world) against the stock GTNH 2.7.4
server pack: **stock** (no jar) vs **fixed** (determinism jar). Each run generates the
spawn-centered radius-15 window (961 chunks) and records every chest inventory, GT ore tile
entity, village piece list, and witchery structure (probe `search=true` reports; raw JSONs are
archived out-of-repo in `results/` because of size — ask if you want the corpus).

Rates are compared as fixed/stock ratios against a ±10% equivalence bound. The verdict CI is a
**seed-paired, region-clustered bootstrap** (4,000 replicates; seeds resample as units, so chests
inside one world are never treated as independent draws and the arms stay paired). `PASS` = 95%
CI inside the bound. `FAIL` requires the 99.9% CI entirely outside it; at that threshold the
expected number of false FAILs across all ~550 rows is ~0.6 (stated in each report header). The
older analytic draw-based CI is retained as a comparison column — it ignores clustering and
overstates certainty for items concentrated in few regions (e.g. dungeon loot).

`inconclusive` means the sample cannot bound the difference at ±10% — mostly rare items. Those
are covered by the direct-code Monte-Carlo tier instead: `roguelike-loot-mc.json` holds 500,000
draws per loot category/level (75 cells, 37.5M draws total) made by calling the *shipped*
Roguelike loot-table code via reflection with a **fixed RNG seed**.

The fixed seed makes this an exact certification rather than a statistical one: on 2026-07-23 the
job was run in three configurations — no jar installed, the 0.4 release jar installed, and the
archived pre-release run — and all three histograms are **byte-identical**
(md5 `bf21f8b059edb62ce2293a77e07f4a10`). With the jar present or absent, 37.5 million draws
through the shipped table code produce bit-for-bit the same output: the jar does not alter any
loot-table code path, so every item's table probability — including the rarest tail entries —
is unchanged *exactly*. What the jar does change about loot is only which Random instance feeds
the draws and how items are delivered to chests; those delivery-level effects are what the
report tables above measure.

## Reports

- `balance-report-bootstrap-oldfixedarm.md` — the 60-seed corpus (120 regions/arm) under the
  bootstrap methodology. **Fixed arm = the pre-release 0.4pre jar**; kept for methodology
  comparison. Headline: 2 FAIL rows of 550 (two rare Tinkers part items in chests, suspected
  artifacts of the old jar's loot path, superseded by the release jar); the previously reported
  fireworks and Alunite deltas do not survive clustering — both were between-seed lottery
  variance, not stable rate shifts.
- `balance-report-0.4.md` — **the authoritative document for upstream PRs**: stock (50 clean
  seeds x 2 repeats = 100 regions) vs the 0.4 release jar (same 50 seeds x 1 = 50 regions),
  all cold runs. Result: **3 FAIL rows of 538** (~0.5 expected false at the 99.9% threshold),
  all ultra-rare chest items (≤0.2 per 100 chests, single-digit observation counts per arm):
  `TConstruct:handGuard:2` (x0.31), `witchery:ingredient:24` (x2.4), `BiomesOPlenty:flippers:0`
  (x3.0). The handGuard row was investigated to closure: it comes from the Tinkers village
  tool-workshop chest — a uniform 145-entry table drawn with the village structure rand through
  vanilla chest-fill code that no mixin touches. Per-seed counts are byte-identical between two
  independent fixed-arm generations (60/60 seeds), confirming the fixed arm is one deterministic
  realization per seed rather than an independent sample; a rare item landing low in that single
  realization is expected tail behavior, not a rate change. The same one-realization argument
  applies to the other two rows. Note the general subtlety for future reports: with the jar,
  "more seeds" is the only way to grow the fixed arm's effective sample — repeats are identical
  by design. Everything
  routing-relevant — all vein materials, small ores, village pieces, witchery structure counts,
  and every common chest item — passes or is centered on 1.0: the previously reported fireworks
  (-33%) and Alunite (+15%) deltas remain non-significant under clustering (point estimates
  0.68 [0.00, 1.98] and 1.16 [0.91, 1.66]).
